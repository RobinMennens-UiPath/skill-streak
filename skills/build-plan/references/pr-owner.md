# Own one pull request

Follow the PR brief as written. Use this procedure in either build mode or as directed by a bug or change playbook.

1. For multiple units, fix the shared contracts first. Write the names and shapes in build/brief-<pr>.md, or a scratch brief for a bug or change. Give each unit a disjoint set of files.
2. If there is only one unit, build it yourself. Otherwise announce the model and effort for the builders, using the requested model or the configured implementer. Resolve them with `orchestrator_capabilities`. Respect the usage floor. Launch one builder per unit in parallel with `delegate_task`, shared isolation, `target.model` and the effort in `target.options`. Begin each task with `Read <absolute path>/delegates.md before anything else.` Use the installed [delegate rules](../../do-work-setup/references/delegates.md), then give the brief path and unit name. Include [coding best practices](../../coding-best-practices/SKILL.md) and [type system](../../type-system/SKILL.md) for typed code. Builders edit only their files and use read-only git. Check the resulting changes against the brief. Reject a unit that copies the old design or misses the plan. Send a fresh builder the brief and reason. After two failures, build the unit yourself.
3. Run the repository checks. Follow the plan's test table. Keep tests that can fail for a real defect. Diagnose failures with [root cause fix](../../root-cause-fix/SKILL.md).
4. Run [fix comments](../../fix-comments/SKILL.md) over the diff and rerun the formatter and linter.
5. Commit by purpose in a few commits.
6. Review the branch with [pr-review](../../pr-review/SKILL.md), run by a different model from the one that wrote the code. Take the configured PR reviewer from the [settings](../../do-work-setup/references/defaults.md). If that model wrote any code for this PR (as builder, PR owner, inline build thread or a request override), use the orchestrator or implementer that did not; if both did, use a swarm member. Never review with a model that wrote the code; if none is left, ask the user. Announce the reviewer model and effort, then start it with `delegate_task`, shared isolation, `target.model` and the effort in `target.options`. Give it the branch, its base, the USER DECISIONS and the brief's required behavior as expectations. Tell it there is no PR yet, so it posts nothing, and that it may start the review agents `pr-review` asks for. Fix the findings you agree with, commit, and push the branch. For a change of more than about 1,000 lines, repeat with a fresh subagent until no significant finding comes back.
7. Follow “Prepare the change”, “Open the draft” and “Write the description” in [open-pr](../../open-pr/SKILL.md). Stop before its later sections. Call `link_pull_request`. For a dependent PR, run `gh stack link <lower> <this>`. Use plain base branches only if the extension is absent.
8. Prove the behavior on the repository's real surface. Record the cases and results.
9. Wait for the PR's CI checks and for review bots such as Copilot. Fix failures this change caused and push. For each bot comment, fix it or decide it does not apply, reply in the thread with what you did, and resolve it. Leave human threads to the user. Repeat until checks are green and no bot comment is open.
10. Return the PR, head, checks, proof and gaps to the calling playbook. In a PR owner thread, deliver this as the last message.
